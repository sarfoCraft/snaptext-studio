WORDTOPDF HOMEPAGE DESIGN REFRESH, VERSION 1.3

This update improves the homepage layout based on the supplied screenshot.

What changed:
- Desktop hero and converter now sit side-by-side instead of leaving a large empty vertical gap.
- The hero has clearer copy, primary/secondary actions, benefit points and file-category chips.
- The Word-to-PDF card has a more visible upload dropzone, document format badge, free-tool label, status feedback and browser-processing note.
- The upload area supports click-to-browse, keyboard activation and drag-and-drop.
- The file selector checks the .docx extension and 25 MB maximum before enabling the Create PDF button.
- Added a 3-step Upload / Prepare / Save PDF explanation.
- The 12 tool cards now have icons, clearer hierarchy and hover/focus feedback.
- Tablet and mobile layouts stack cleanly and reduce card density.
- Existing WordToPDF IDs, tool routes, theme toggle, privacy policy, ad placeholders and GitHub Pages base-path fix are preserved.

Important behavior:
The tool prepares a print-ready page and opens the browser print dialog. The visitor still chooses "Save as PDF". It does not silently download a PDF file.

Validation:
- Homepage HTML parsed.
- No duplicate IDs on homepage.
- All 12 tool cards are present.
- Required converter IDs are present.
- JavaScript syntax checks passed for runtime.js and site.js.
- Responsive CSS and the existing GitHub Pages base-path logic remain included.

Deployment:
Upload the CONTENTS of the extracted ZIP to the root of sarfocraft/snaptext-studio and commit to the branch used by GitHub Pages. The package also remains compatible with Cloudflare Pages and the custom domain root path.
