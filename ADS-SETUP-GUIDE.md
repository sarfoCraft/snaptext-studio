# WordToPDF: Ad Network Setup Guide

This package is prepared for Adsterra display banners and Monetag In-Page Push (Banner). It does not contain live publisher tags because the unique tags and zone IDs must be generated inside your own publisher accounts.

## What is prepared

- One Adsterra 300 x 250 medium-rectangle banner placeholder per monetized page. This size fits a 300px mobile content column and desktop layouts.
- One Adsterra placement per monetized page, positioned outside the file upload/conversion workspace.
- Monetag In-Page Push (Banner) head-tag placeholder on the homepage, tool pages, and article pages.
- Privacy Policy and Terms of Use disclosures for both advertising providers.
- Root-level `ads.txt` placeholder. It contains comments only until the networks provide seller records.

## 1. Adsterra setup

1. Register or sign in at https://beta.publishers.adsterra.com/.
2. Add and submit `wordtopdf.fun` for review.
3. After the website is approved, create a Banner ad unit for 300 x 250.
4. Copy the exact code generated for that unit.
5. In every monetized HTML page, find the `adsterra-300x250-<page>` container and replace its comment with the exact 300 x 250 code.
6. Remove the `hidden` attribute from the surrounding `.wtd-ad-slot` element after inserting the real code.
7. Use the generated zone only once per page. The same zone can be reused on different pages if Adsterra's dashboard permits it.

Adsterra also lists other banner sizes such as 728 x 90, 320 x 50 and 468 x 60. This package uses 300 x 250 to keep one ad zone per page and avoid loading hidden desktop and mobile tags. If your dashboard only offers another size, ask for a matching layout update first.

## 2. Monetag setup

1. Register or sign in at https://monetag.com/.
2. Add `wordtopdf.fun` in the Websites section.
3. Verify the website using the method shown in your dashboard. Monetag supports a verification file in the site root or a verification meta tag in the page head.
4. Create an **In-Page Push (Banner)** zone if you want a native-style on-page banner. It is not a fixed 728 x 90 rectangular banner. Monetag says this tag belongs in the `<head>` section.
5. Copy the exact tag generated by Monetag.
6. In each monetized HTML page, find `MONETAG IN-PAGE PUSH (BANNER) TAG START` inside `<head>` and paste the tag there, once on that page.
7. Preserve `data-cfasync="false"` exactly if it is included in the tag. Do not rewrite the network URL or zone ID.
8. Use Monetag's Installation Check in the dashboard.

If you choose Vignette Banner instead, it appears as an overlay in the middle of the page. That is a different user experience. Do not add it as if it were a normal inline banner.

## 3. Cloudflare notes

- Monetag confirms its tags work with Cloudflare. Its tag includes `data-cfasync="false"` to prevent Rocket Loader from delaying the script.
- If Monetag impressions do not appear, check that this attribute remains in the published HTML. If needed, disable Rocket Loader or exclude the affected pages from it.
- Do not add both a Monetag In-Page Push tag and another Monetag tag for the same zone on the same page.
- Keep ad scripts out of the file-processing runtime. Do not place ads between file selection, conversion controls, progress messages or download buttons.

## 4. ads.txt

Open the root-level `/ads.txt` file and append only the exact seller records provided by the Adsterra and Monetag dashboards or support teams. Do not make up publisher IDs or seller records. Publish the updated file and confirm it opens at:

https://wordtopdf.fun/ads.txt

## 5. Privacy and consent

The Privacy Policy now describes the possible use of Adsterra and Monetag, the types of browser/device information that advertising tags may process, advertising purposes, third-party sharing, and links to provider information.

This is a starter disclosure, not legal advice and not a certified consent-management platform. Actual disclosures must be checked against the exact tags, formats, cookies, countries served and current provider policies. If applicable law requires consent before non-essential cookies or advertising identifiers are used, configure an appropriate consent-management platform and make sure the tags respect the visitor's choice before activation.

Replace the contact placeholder with a real support/privacy email before launch.

## 6. Testing

- Test on desktop and mobile.
- Test in a private/incognito browser with ad blockers disabled.
- Use each network's installation check.
- Confirm ads do not cover upload buttons, conversion controls, download links or privacy notices.
- Confirm only one responsive Adsterra slot is visible at each viewport width.
- Check that the page remains usable if an ad is blocked or does not fill.
- Never click your own ads, ask others to click them, or use bots/incentives to create impressions or clicks.
